# Roadmap

The roadmap is evidence-gated. Dates should be set only after capacity, partners, data access, and pilot scope are confirmed.

## Stage 0: Concept and workflow prototype

Status: current

- articulate the opportunity-intelligence thesis;
- demonstrate the core product loop;
- define opportunity classifications;
- make fictional data unmistakable;
- document methodology, architecture, and safety boundaries;
- test whether users understand the difference between a pathway and a verified live offer.

## Gate 1: Curated evidence pilot

Proceed when the team has selected one geography, a narrow set of categories, and named review ownership.

- curate an initial catalog from authoritative sources;
- store provenance, terms, verification history, and availability state;
- create reviewer workflows and correction handling;
- replace illustrative scores with explainable rule-based matching;
- conduct usability and trust testing with a small pilot group;
- measure stale-data rate, correction rate, and user comprehension.

## Gate 2: Functional MVP

Proceed when the curated pilot demonstrates reliable verification and understandable recommendations.

- add authentication and consent controls;
- add user profiles and saved pipelines;
- connect scheduled ingestion for approved sources;
- add deadline and reverification notifications;
- add provider and user reporting workflows;
- instrument the complete discovery-to-action funnel.

## Gate 3: Responsible intelligence layer

Proceed when structured matching and review operations are stable.

- use AI for bounded extraction and plain-language explanation;
- introduce conflict and anomaly detection;
- add human review thresholds and audit logs;
- evaluate recommendation quality across different user groups;
- document model limitations and rollback criteria.

## Gate 4: Partnership and scale

Proceed when the product has evidence of trustworthy outcomes and sustainable operations.

- build provider and institutional partnerships;
- expand geography and categories incrementally;
- offer partner analytics without exposing personal eligibility data;
- evaluate employer, university, nonprofit, and public-sector distribution;
- test business models that do not reward low-quality listings or exploit user need.

## Candidate success measures

These are proposed measures, not current results:

- percentage of live records with complete authoritative provenance;
- percentage of records verified within the required service level;
- user ability to distinguish verified, conditional, and illustrative information;
- time from discovery to a verified next action;
- application completion and user-reported outcome rates;
- correction, complaint, and stale-data rates;
- user trust and perceived control;
- value claimed only when supported by user-confirmed outcomes.
